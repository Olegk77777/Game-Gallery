# CLAUDE.md — Game Gallery

Проектная памятка для Claude Code. Дополняет глобальный `~/.claude/CLAUDE.md`.
Здесь — как устроен сайт, как добавлять контент и как он деплоится, чтобы не исследовать проект каждый раз заново.

## Что это

**Game Gallery** — кинематографичная витрина игровых скриншотов (21:9). Куратор — Олег.
Сайт статический, хостится на **GitHub Pages**: https://olegk77777.github.io/Game-Gallery/
Репозиторий: `Olegk77777/Game-Gallery` (origin), деплой-ветка — `main`.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · экспорт в статику (`output: 'export'`).
Шрифты — Instrument Serif + Hanken Grotesk (`next/font/google`). Стили — один файл `src/app/globals.css` (CSS-переменные, без CSS-модулей).

## Как работает галерея (поток данных)

1. Картинки лежат в `public/gallery/<Название игры>/`.
2. При сборке `page.tsx` зовёт `getGames()` из `src/lib/gallery.ts`, которая **читает файловую систему напрямую** — сканирует папки игр, картинки и `.txt`-подписи.
3. Данные уходят в `GalleryExperience.tsx`, который рендерит весь интерфейс.

То есть **источник правды — это файлы в `public/gallery/`**, а не код или JSON. Чтобы добавить/убрать контент, код трогать не нужно.

## Контент: игры, кадры, подписи

(Подробнее и «для человека» — в `src/data/HOW_TO_ADD_GAMES.md`.)

- **Новая игра** = новая папка `public/gallery/<Точное название>/`. Имя папки = ключ игры.
- **Новый кадр** = файл картинки (`.jpg` / `.jpeg` / `.png` / `.webp`) в папке игры.
- **Подпись кадра** = текстовый файл `.txt` с **тем же именем**, что и картинка, рядом с ней (UTF-8).
  Пример: `V16.jpeg` → `V16.txt`. Нет `.txt` — кадр просто без подписи.
  Стиль подписей: короткая, атмосферная фраза на английском (см. существующие).
- **Кириллица и пробелы в именах файлов — допустимы** (на фронте пути проходят через `encodeURI`).
- Кадры сортируются по имени файла; **игры** — особая сортировка в `gallery.ts`: «The Witcher 3 Wild Hunt» всегда первый, остальные по алфавиту.
- При **удалении** кадра убирай заодно его `.txt` (иначе остаётся «осиротевшая» подпись) и, по желанию, превью в `hero-gallery/`.
- Снимаешь в `.exr`? Сначала `scripts/convert-exr-to-png.sh` (конвертит все `.exr` в `gallery/` в `.png`).

### Метаданные игры (название, место, год, цвет)

Хранятся в объекте `GAME_META` в начале `src/components/GalleryExperience.tsx`. Ключ — точное имя папки игры. Поля: `title`, `full`, `place`, `year`, `accent` (цвет-акцент). Для игр без записи в `GAME_META` берётся дефолт (имя папки + цвет по кругу). Хочешь красивое имя/место/год/цвет для новой игры — добавь запись в `GAME_META`.

## Оптимизация картинок (важно понимать)

`scripts/optimize-gallery.js` рекурсивно берёт **все** картинки из `gallery/` и делает по три webp-варианта в `public/optimized-gallery/<Игра>/`:

| вариант | ширина | где используется |
|---|---|---|
| `full`  | 2560px | hero на главной, полноэкранный просмотр |
| `card`  | 1400px | карточки барабана |
| `thumb` | 360px  | миниатюры |

`lib/gallery.ts` выбирает источник по приоритету: **webp-вариант → hero-превью → оригинал**.

**Ключевой момент:** на CI шаг `prebuild` (`npm run build` → `optimize-gallery`) генерит webp для всех картинок автоматически. Поэтому **новый кадр после деплоя показывается сам** — ничего вручную оптимизировать не надо. `optimized-gallery/` в `.gitignore` (пересоздаётся при каждой сборке).

- **`hero-gallery/`** — старый запасной механизм (jpg-превью). Нужен, только если webp-варианта нет. Новым кадрам не требуется. Превью удалённых кадров можно чистить.
- **`src/data/games.json`** — генерится `sync-gallery.js`, **но фронтом напрямую не используется** (рендер идёт через `getGames()` из ФС). По сути билд-артефакт; CI его перегенерит, отдельно поддерживать не нужно.

## Интерфейс и поведение (что уже реализовано)

Навигация через **hash-роутинг** (без серверной маршрутизации, т.к. статика):
`#/` — главная · `#/a/<gameId>` — альбом · `#/a/<gameId>/<n>` — кадр на весь экран.
`gameId` — это slug имени игры (функция `slugify`).

Компоненты в `GalleryExperience.tsx`:
- **Hero** — главный экран, сам прокручивает избранные кадры.
- **Collections** — список альбомов (игр).
- **AlbumView** + **Carousel3D** — 3D-«барабан»: карточки крутятся.
  - Листание **только кручением барабана** (drag мышью/тачем + колесо/трекпад). Стрелок нет, есть точки-индикаторы.
  - **Инерция**: резкий «бросок» → барабан летит и плавно тормозит, прилипая к ближайшему кадру. Остановить — коснуться/схватить. И drag, и колесо подкручивают один «маховик» (скорость в `velocity`, кадровый цикл в `runMomentum`/`addSpin`).
  - Размер карточек — формула `cardWidth` в `Carousel3D` (зависит от ширины/высоты сцены).
  - Подсказка «drag to rotate» (`.av-hint`) вынесена **над** карточкой.
- **Lightbox** — полноэкранный кадр. Клик по картинке / Esc / свайп вниз — закрывают (возврат в барабан). Листания внутри НЕТ (ни стрелок, ни ленты миниатюр) — кадры смотрят, вращая барабан.
- **Preloader**, **SoundToggle** (фоновый звук).

## Деплой

- Триггер — **push в `main`**. Workflow `.github/workflows/deploy.yml` (GitHub Pages).
- Шаги: `npm ci` → `npm run build` (а он сперва `optimize-gallery` + `sync-gallery`) → статика в `out/` → публикация на Pages. Обычно 1–2 минуты.
- `basePath` подставляется автоматически на Pages (через `configure-pages`, = `/Game-Gallery`). Локально пусто.
- Простой контентный апдейт (по HOW_TO_ADD_GAMES.md): `git add . && git commit -m "..." && git push`.
- Проверить статус: вкладка Actions в репозитории или `gh run list --workflow deploy.yml`.

## Особенности и грабли

- `output: 'export'` → чистая статика: нет серверных функций/ISR, `next/image` без оптимизации (`unoptimized: true`).
- `optimized-gallery/` и `.DS_Store` — в `.gitignore`; webp коммитить не нужно.
- Имена файлов с кириллицей/пробелами в shell — всегда в кавычках; в git выводе показываются escape-последовательностями (это нормально).
- Удалил кадр — проверь, что не осталось его `.txt` (подпись) и `hero-gallery`-превью.
