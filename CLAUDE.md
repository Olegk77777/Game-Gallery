# CLAUDE.md — Game Gallery

Проектная памятка для Claude Code. Дополняет глобальный `~/.claude/CLAUDE.md`.
Здесь — как устроен сайт, как добавлять контент и как он деплоится, чтобы не исследовать проект каждый раз заново.

---

## Что это

**Game Gallery** — кинематографичная витрина игровых скриншотов (21:9). Куратор — Олег.
Сайт статический, хостится на **GitHub Pages**: https://olegk77777.github.io/Game-Gallery/
Репозиторий: `Olegk77777/Game-Gallery` (origin), деплой-ветка — `main`.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · экспорт в статику (`output: 'export'`).
Шрифты — Instrument Serif + Hanken Grotesk (`next/font/google`). Стили — один файл `src/app/globals.css` (CSS-переменные, без CSS-модулей).

## Как работает галерея (поток данных)

1. Картинки лежат в `public/gallery/<Название игры>/`.
2. При сборке `page.tsx` зовёт `getGames()` из `src/lib/gallery.ts`, которая **читает файловую систему напрямую** — сканирует папки игр, картинки и `.txt`-подписи.
3. Данные уходят в `GalleryExperience.tsx`, который рендерит весь интерфейс.

То есть **источник правды — это файлы в `public/gallery/`**, а не код или JSON. Чтобы добавить/убрать контент, код трогать не нужно.

## Контент: игры, кадры, подписи

(Подробнее и «для человека» — в `src/data/HOW_TO_ADD_GAMES.md`.)

- **Новая игра** = новая папка `public/gallery/<Точное название>/`. Имя папки = ключ игры.
- **Новый кадр** = файл картинки (`.jpg` / `.jpeg` / `.png` / `.webp`) в папке игры.
- **Подпись кадра** = текстовый файл `.txt` с **тем же именем**, что и картинка, рядом с ней (UTF-8).
  Пример: `V16.jpeg` → `V16.txt`. Нет `.txt` — кадр просто без подписи.
  Стиль подписей: короткая, атмосферная фраза на английском (см. существующие).
- **Кириллица и пробелы в именах файлов — допустимы** (на фронте пути проходят через `encodeURI`).
- Кадры внутри альбома сортируются по имени файла. **Альбомы (игры) сортируются по свежести** в `gallery.ts`: чем недавнее обновление папки (новый альбом или добавленный кадр), тем выше. Сигнал — время последнего git-коммита, тронувшего папку игры (фолбэк — mtime файлов). Поэтому в `deploy.yml` у `actions/checkout` стоит `fetch-depth: 0` (нужна полная история).
- При **удалении** кадра убирай заодно его `.txt` (иначе остаётся «осиротевшая» подпись) и, по желанию, превью в `hero-gallery/`.
- Снимаешь в `.exr`? Сначала `scripts/convert-exr-to-png.sh` (конвертит все `.exr` в `gallery/` в `.png`).

### Метаданные игры (название, место, год, цвет, обложка)

Хранятся в объекте `GAME_META` в начале `src/components/GalleryExperience.tsx`. Ключ — точное имя папки игры. Поля: `title`, `full`, `place`, `year`, `accent` (цвет-акцент) и необязательный `cover`. Для игр без записи в `GAME_META` берётся дефолт (имя папки + цвет по кругу). Хочешь красивое имя/место/год/цвет для новой игры — добавь запись в `GAME_META`.

**Обложка альбома** (картинка в списке Collections) по умолчанию — первый кадр по сортировке имён. Чтобы назначить обложкой конкретный кадр, добавь в запись игры поле `cover` с **точным именем файла** кадра (с расширением). Если файла с таким именем нет — тихо берётся первый кадр. Кадр-обложка также **встаёт первым в барабане** альбома — `toGalleryGame` поднимает его в начало `shots`, поэтому барабан стартует именно с обложки. Пример:
```ts
"Cyberpunk 2077": { ..., cover: "Cyberpunk 2077® 2026.06.05 - 19.43.16.09 копия.jpg" },
```

## Оптимизация картинок (важно понимать)

`scripts/optimize-gallery.js` рекурсивно берёт **все** картинки из `gallery/` и делает по три webp-варианта в `public/optimized-gallery/<Игра>/`:

| вариант | ширина | где используется |
|---|---|---|
| `full`  | 2560px | hero на главной, полноэкранный просмотр |
| `card`  | 1400px | карточки барабана |
| `thumb` | 360px  | миниатюры |

`lib/gallery.ts` выбирает источник по приоритету: **webp-вариант → hero-превью → оригинал**.

**Ключевой момент:** на CI шаг `prebuild` (`npm run build` → `optimize-gallery`) генерит webp для всех картинок автоматически. Поэтому **новый кадр после деплоя показывается сам** — ничего вручную оптимизировать не надо. `optimized-gallery/` в `.gitignore` (пересоздаётся при каждой сборке).

- **`hero-gallery/`** — старый запасной механизм (jpg-превью). Нужен, только если webp-варианта нет. Новым кадрам не требуется. Превью удалённых кадров можно чистить.
- **`src/data/games.json`** — генерится `sync-gallery.js`, **но фронтом напрямую не используется** (рендер идёт через `getGames()` из ФС). По сути билд-артефакт; CI его перегенерит, отдельно поддерживать не нужно.

## Интерфейс и поведение (что уже реализовано)

Навигация через **hash-роутинг** (без серверной маршрутизации, т.к. статика):
`#/` — главная · `#/a/<gameId>` — альбом · `#/a/<gameId>/<n>` — кадр на весь экран.
`gameId` — это slug имени игры (функция `slugify`).

Компоненты в `GalleryExperience.tsx`:
- **Hero** — главный экран, сам прокручивает избранные кадры.
  - **Ken Burns**: каждый кадр медленно наезжает со сдвигом (CSS `@keyframes hero-kenburns` на `.frame-img`, траектории — таблица `HERO_KB`, своя для каждого кадра).
  - **Параллакс по курсору**: фон шапки мягко смещается за мышью. JS пишет CSS-переменные `--px/--py` на `.hero` (раз в кадр через rAF), `.hero-media` доводит сдвиг CSS-переходом. Текст не двигается. Только десктоп (`pointer: fine`).
  - **Луч проектора** (`.hero-beam` → `.hero-beam-shaft`, между `.hero-media` и `.hero-grade`): объёмный «дышащий» световой клин (`@keyframes beam-breathe`), тонируется в акцент альбома через `--beam` (зарегистрирован `@property`, плавно перетекает на кросс-фейде). Снос за курсором — на внешнем слое (`--px/--py`), «дыхание» — на внутреннем, чтобы трансформы не клобберились. opacity ≤0.13, `mix-blend: screen`, `will-change`+`contain`. Это **Layer 1**; canvas-пылинки (Layer 2) сознательно отложены.
- **Collections** — список альбомов (игр).
  - **Появление по скроллу**: строки всплывают по очереди при входе в экран (IntersectionObserver добавляет класс `.in`). Стартовое «спрятанное» состояние включается классом `is-ready` на секции — он ставится **только когда JS готов раскрыть** (без JS контент виден сразу). Задержка-каскад — `transitionDelay` по индексу строки.
  - **Пятно света за курсором** (`.spotlight`): янтарный ореол едет за мышью через `transform` (CSS-переменные `--mx/--my`, класс `spot`). Только десктоп.
  - **Бликовый «глянец»** на обложке альбома (`.album-thumb::after`): при наведении по кадру пробегает полоса света.
- **AlbumView** + **Carousel3D** — 3D-«барабан»: карточки крутятся.
  - Листание **только кручением барабана** (drag мышью/тачем + колесо/трекпад). Стрелок нет, есть точки-индикаторы.
  - **Инерция** (drag мышью/тачем и свайп трекпада): резкий «бросок» → барабан летит и плавно тормозит, прилипая к ближайшему кадру. Остановить — коснуться/схватить (скорость в `velocity`, кадровый цикл в `runMomentum`/`addSpin`).
  - **Колесо мыши — дискретный шаг**: один щелчок = ровно одна карточка (реагирует с первого щелчка, не проскакивает пачками). В `onWheel` строчные/крупные пиксельные события идут через `go`, а мелкий пиксельный поток (трекпад) — через инерцию.
  - **Скоростной ореол**: при раскрутке за карточками вспыхивает свечение в цвет альбома и гаснет вместе с инерцией. JS пишет переменную `--spin` (0..1) по текущей скорости (`setSpin`), яркость `.stage3d::before` = `calc(var(--spin)*0.42)`.
  - **Блик на активной карточке** (`.gloss`, вариант в `state` `gloss`, выбор — `pickGloss`): чтобы не приедался, каждый проход — случайный. ~70% — **вспышка** (`gloss-flash`, `@keyframes card-gloss-flash`): мягкое пятно в случайной точке кадра, три «характера» (spark/glint/bloom — мелкая-яркая-быстрая … крупная-тусклая-медленная). ~30% — **луч** (`gloss-sweep`, `@keyframes card-gloss-sweep`): полоса света по одному из 8 векторов. Вариант перевыбирается при смене активной карты и в конце каждого цикла (`onAnimationIteration`); рестарт анимации — через `key` на span. Параметры — CSS-переменные (`--g-*`).
  - Размер карточек — формула `cardWidth` в `Carousel3D` (зависит от ширины/высоты сцены).
  - Подсказка «drag to rotate» (`.av-hint`) вынесена **над** карточкой.
- **Lightbox** — полноэкранный кадр. Клик по картинке / Esc / свайп вниз — закрывают (возврат в барабан). Листания внутри НЕТ (ни стрелок, ни ленты миниатюр) — кадры смотрят, вращая барабан.
  - **Push-In** (FLIP-«наезд камеры»): при открытии кликнутая карта барабана физически доезжает до полного экрана, при закрытии (клик/Esc) — улетает обратно в свой слот. Прямоугольник карты замеряется на клике и прокидывается `Carousel3D → AlbumView (state) → Lightbox`; морф — инлайн-`transform` (`morphStyle`), только композитно. Тяжёлый оригинал (`fullSrc`) грузится через `img.decode()` уже **после** наезда. Свайп вниз закрывает прежним мягким сворачиванием (не морфит). Фолбэк на обычное появление, если карту не померить или `prefers-reduced-motion`.
- **Preloader**, **SoundToggle** (фоновый звук).

**Производительность и доступность анимаций.** Все «фишечные» эффекты идут только через GPU-свойства (`transform`/`opacity`), без библиотек и WebGL — вес бандла не растёт. Курсорные эффекты (параллакс, пятно света) включаются только на десктопе (`hasFinePointer()`), пишут CSS-переменные раз в кадр через `requestAnimationFrame` и при `prefers-reduced-motion` не запускаются вовсе; CSS-анимации в этом режиме глушит глобальный `@media (prefers-reduced-motion: reduce)` блок. Хук `usePrefersReducedMotion` — единая точка проверки.

## Деплой

- Триггер — **push в `main`**. Workflow `.github/workflows/deploy.yml` (GitHub Pages).
- Шаги: `npm ci` → `npm run build` (а он сперва `optimize-gallery` + `sync-gallery`) → статика в `out/` → публикация на Pages. Обычно 1–2 минуты.
- `basePath` подставляется автоматически на Pages (через `configure-pages`, = `/Game-Gallery`). Локально пусто.
- Простой контентный апдейт (по HOW_TO_ADD_GAMES.md): `git add . && git commit -m "..." && git push`.
- Проверить статус: вкладка Actions в репозитории или `gh run list --workflow deploy.yml`.

## Особенности и грабли

- `output: 'export'` → чистая статика: нет серверных функций/ISR, `next/image` без оптимизации (`unoptimized: true`).
- `optimized-gallery/` и `.DS_Store` — в `.gitignore`; webp коммитить не нужно.
- Имена файлов с кириллицей/пробелами в shell — всегда в кавычках; в git выводе показываются escape-последовательностями (это нормально).
- Удалил кадр — проверь, что не осталось его `.txt` (подпись) и `hero-gallery`-превью.
