# Game Gallery Studio

Отдельный менеджер альбомов для Game Gallery. Работает на компьютере и открывается в браузере. Учётная запись GitHub уже настроена на этом Mac.

## Запуск

Дважды нажмите **«Менеджер альбомов.command»** в корне проекта. Откроется студия. Окно запуска можно свернуть; закрыть приложение — кнопкой **«Завершить работу студии»** внизу страницы. Повторный запуск открывает уже работающую студию.

На Windows предусмотрен **Album Manager.cmd**. Для первого запуска там нужны Node.js LTS, Git и вход в GitHub с разрешением отправлять изменения в этот репозиторий. Windows-версия запускного файла подготовлена, но на Windows не проверялась.

Запуск из терминала: `npm run albums`. Адрес студии: `http://127.0.0.1:4318`.

## Работа с коллекцией

1. Выберите игру слева или создайте новый альбом кнопкой **+**.
2. Нажмите **«Добавить кадры»** или перетащите файлы в открытый альбом. Можно загружать несколько снимков сразу: JPG, PNG и WebP, до 64 МБ на файл.
3. Нажмите на кадр, введите подпись и выберите **«Сохранить подпись»**. Сочетание ⌘S на Mac / Ctrl+S на Windows также сохраняет открытую форму.
4. Выберите **«Оформление»**, чтобы изменить названия, место, год, цвет и обложку. В окне кадра тоже есть кнопка **«Сделать обложкой»**.
5. Для удаления используйте корзину на карточке. Для нескольких кадров отметьте их флажками и нажмите **«Удалить»**. Оригиналы, подписи и старые превью сохраняются в локальной корзине. Кнопка **«Восстановить»** возвращает их в альбом.

Подпись можно оставить пустой. Пустой альбом хранится в менеджере, но на сайте появляется после добавления первого кадра. При совпадении имени снимок получает суффикс `(2)`, `(3)` и т. д.; существующие кадры не перезаписываются. HDR-файлы JXR и EXR нужно предварительно конвертировать существующими скриптами проекта.

## Публикация

**Автопубликация включена по умолчанию.** Примерно через 6 секунд после последнего сохранения менеджер собирает изменения и отправляет их на GitHub. Загрузка нескольких файлов публикуется одной пачкой. Чтобы сначала подготовить всю подборку, выключите переключатель и нажмите **«Опубликовать»**, когда будете готовы.

Нижняя полоса показывает три разных этапа: сохранено на компьютере → отправлено на GitHub → опубликовано на сайте. Сборка GitHub Pages обычно занимает 1–3 минуты. Сам менеджер в публичный сайт не встраивается.

Если интернет пропал, файлы остаются на компьютере. Верните подключение и нажмите **«Повторить публикацию»**. Если коммит уже создан, сначала завершите его отправку; после этого можно редактировать дальше. Перезапуск не стирает очередь. Очередь, оставшаяся от прошлого запуска, отправляется кнопкой публикации, а не без предупреждения при открытии.

Менеджер отправляет только файлы, которые вы изменили через него. Он не включает в публикацию посторонний код, черновики и подготовленные в другом приложении изменения. Если локальная история и GitHub отличаются, менеджер остановит публикацию с объяснением. В этом случае нужно сначала синхронизировать проект; принудительного перезаписывания истории нет.

Закрытие одной вкладки не останавливает локальный процесс и уже запланированную отправку. Чтобы приостановить отправку, выключите автопубликацию. Для полного выхода после завершения публикации нажмите **«Завершить работу студии»**.

## Где находятся данные

- Кадры и подписи: `public/gallery/<игра>/`.
- Оформление: `src/data/album-meta.json`. Этот файл читает и сайт, и менеджер.
- Локальная корзина, настройки, очередь и превью: `.album-manager/`. Папка исключена из Git и не публикуется. Корзина сама не очищается.
- Код студии: `album-manager/`; запускные файлы лежат в корне проекта.

Сервер слушает только `127.0.0.1`, проверяет адрес запроса и локальный токен, не принимает запросы с других сайтов. Пароли и токены GitHub не передаются в браузер: используется уже настроенный Git на компьютере.

## Проверка для разработки

- `npm run test:albums` — реальные файловые операции и push во временный локальный bare-репозиторий; работающий сайт не меняется.
- `node album-manager/tests/ui-fixture.mjs` — отдельная тестовая студия на порту 4319. Путь к тестовой папке и файлу загрузки печатается при запуске. Её origin указывает на локальный тестовый репозиторий.
- `npm run lint`, `npx tsc --noEmit`, `npm run build` — проверки всего проекта.

Публикация использует отдельный временный Git-индекс и фиксирует ожидаемый коммит перед перемещением HEAD. Поэтому посторонние staged-файлы сохраняют своё состояние, а незавершённый push можно продолжить после перезапуска. Удаление и восстановление сериализованы с публикацией.
